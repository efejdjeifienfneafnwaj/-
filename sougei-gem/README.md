## 全体の流れ

```
設定シート（①施設・車両 ②利用者）
   │ 🚐① 座標を作る        → ③座標（Googleジオコーダ）
   │ 🚐④ 実測時間を取る    → ⑤実測（Googleマップ経路。事業所↔全住所＋近い10件）
   │ 🚐② Gem用テキストを作る → ダイアログ＋Googleドキュメント「送迎データ（Gem用・自動更新）」
   ▼
Gem「送迎配車アシスタント」
   指示：Gem指示文_A1.md
   知識：配車ロジック.py ＋ 送迎データ（Gem用・自動更新）
   設定：コード実行ON、モデルPro
   → 入力部分（CONFIG/VEHICLES/USERS/STAFF/REAL）を書き換えて実行 → 送迎表
```

`🚐③ Gemの準備（初回だけ）` は `_payload` から `配車ロジック.py` を同じフォルダに書き出し、指示文を表示する。

## 配車ロジックの手順（配車ロジック.py）

1. 住所＋お迎え時刻が同じ人をひとまとめにする
2. 貪欲法で車に割り当てる（介護は車いす・歩行器の方を先に。時刻差30分超は同乗させない）
3. 車内の順番：最近傍法で回り、指定時刻／到着見込みで並べ替え
4. 4000回のシャッフルで移動時間の合計を短縮（seed固定で毎回同じ結果）
5. 時刻計算：停車1回ごとに乗降時間。指定時刻より早ければ待機
6. 2便の判断（介護のみ）：1便に乗り切らない、または6軒以上で平均10分以上早くなる場合
7. 移動時間は `REAL`（実測）を優先し、無ければ直線距離×factor

サンプルデータで実行すると、3台に10名が割り当てられ、未割当なし・警告なしで終わる。

## 現状の食い違い・未対応（シートとGemの間）

| # | 内容 | 影響 |
|---|---|---|
| 1 | `②Gem用テキスト` が **「事業区分：放デイ」「便：お迎え」「乗降5分」を固定で出力**している | 介護事業所で使うと、2便なし・出発時刻の逆算モードになる |
| 2 | ①シートに**車いす・歩行器の積載欄がない**。テキストも `車両名/定員/可` だけ | `wc_max` が入らず、車いす利用者が全員「未割当（車いす不可）」になる |
| 3 | ②シートに**移動区分（車いす／歩行器）の列がない**。テキストにも出ない | 積載制限がそもそも効かない（全員「なし」扱い） |
| 4 | ②シートの**利用曜日（月〜土の○）を読んでいない** | その日に来ない人も含めて全員で配車される |
| 5 | 曜日セルに時刻を書く運用（シートの注記どおり）を読んでいない | 曜日ごとのお迎え時刻が反映されない |
| 6 | お送り（帰り便）のテキストを作れない。お送り先住所・時刻は読んでいるが使っていない | 帰りの配車ができない |
| 7 | `④職員` シートがテンプレートに無い（手順書で先方に手作りさせている） | 作り忘れると運転手がすべて「運転手不足」 |
| 8 | 「③ Gemの準備」のダイアログに**コード実行ON・Pro選択の案内がない**（手順書にだけある） | いちばん失敗しやすい2点が画面で案内されない |
| 9 | 指示文 5章が「時刻は直線距離の概算」と必ず言わせる | 実測を使ったときの `配車ロジック.py` の表示（実測値をもとに計算）と矛盾する |
| 10 | 最新版と旧版で `LOGIC_VERSION` がどちらも `2026-09-15` | 1行目の版表示で新旧を見分けられない |
| 11 | ④実測がお送り先住所の区間も測っている | 帰り便が未対応のうちは測定時間が余分にかかる |

1〜3は介護で使うと結果が変わる。放デイ前提で作られたテキスト出力に、介護向けの計算ロジックが載っている状態。

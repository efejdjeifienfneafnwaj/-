# 送迎表（スプレッドシート版）

放デイ・介護の送迎を、Googleスプレッドシートだけで組む仕組み。
先方は名簿（①②）を直すだけで、曜日ごとの送迎表が自動で作り直される。

## ファイル

| ファイル | 役割 |
|---|---|
| `設定シート.xlsx` | 配布用のひな形。①施設・車両設定 / ②利用者一覧 |
| `送迎メニュー.gs` | シートのApps Script。これ1つを貼れば動く |
| `導入手順.md` | 船井の導入作業と、先方の日々の使い方 |
| `配車ロジック.py` | 配車の計算の元になった Python 版（版 2026-09-24）。スクリプトはこれと同じ結果を出す |
| `tools/python版と比べる.js` | スクリプトの計算が Python 版と一致するかを確かめる（架空データ） |

## 流れ

```
①② を直す ──(1時間ごと・名簿が変わったときだけ)──▶
  住所を整える → ③座標（Googleジオコーダ。一度調べた住所は二度と調べない）
             → ④実測（Googleマップの経路。事業所↔全住所 と 各住所から近い10件。測った区間は保存）
             → 「月曜の送迎表」〜「土曜の送迎表」
送迎表の黄色い欄（使わない車・お休み・別案）を直す ──(すぐ)──▶ その曜日だけ組み直す
```

メニューは「今すぐ送迎表を作り直す」「【初回】自動更新をONにする」の2つ。
トリガーは1時間ごとの `自動更新` と、入力欄を見張る `入力が変わった`（編集時）。

## ②の曜日セルの書き方

| 書き方 | 意味 |
|---|---|
| `○(迎え14:10、送り17:55)` | お迎え先へ14:10、お送り先へ17:55 |
| `○(迎え14:45、送りなし)` | お迎えだけ |
| `○(自宅迎え9:40、送り16:05)` | 場所つき。「自宅」「祖父母宅」は B・D列の名前や「○○住所」列から住所を探す |
| `○(迎え14:10/クラブ活動あり15:00、送り18:05)` | 「/」の後ろは別案。送迎表の「別案で送迎する方」に書いた日だけ使う |
| `○(迎えなし、送りなし/送りあり：14:15)` | 普段は無し。別案の日だけ送る |
| `○(自力16:00、送り17:50)` | 「自力」「各自」「保護者」の区間は送迎しない |
| `○` / `14:35` | F列・G列の時刻を使う / その曜日だけのお迎え時刻 |

## 配車の計算

`送迎メニュー.gs` の「配車の計算」は `配車ロジック.py` を一行ずつ移したもの。
Python の乱数（メルセンヌ・ツイスタ）と `round`（偶数への丸め）も同じ動きにしてあり、同じ入力なら同じ送迎表になる。

Python 版から変えた点は1つだけ。
**組み直しの改善で、指定時刻への遅れ1分を走行5分ぶんの損として数える**（`LATE_WEIGHT = 5`）。
Python 版は走行時間だけを縮めるため、遅れを出してでも1台に詰め込む組み方を選ぶことがあった。
`LATE_WEIGHT` を 0 にすると Python 版と同じ動きに戻る（比べるテストは 0 で行う）。

時刻が60分以上あく所で便を分け（保育園の便と小学校の便など）、どの便でも全車を使えるようにしている。

## 確認したこと

- Python 版との一致：先方の実データ21便（座標は仮）、ランダムな介護・放デイ100件で出力が1行残らず一致
- 遅れの損を入れた効果：実データ（座標は仮）で遅れの合計 1851分 → 1053分
- 先方の実データ46名で、月〜土の送迎表シートを作成（約5秒）。入力欄（使わない車・お休み・別案）が効くこと
- 「自力」、①の1行目のタイトルを車両欄と取り違える不具合は、実際のシートで見つかって直した

## まだ確認していないこと

- Google 上での実行時間（手元では全曜日で約5秒。Apps Script は数倍遅い見込み）
- 2便に分けたほうが早い場合の分け方（介護のみ。まれにしか起きず、ランダムテストでも一度も起きなかった）

先方の実データ（名簿）はこのリポジトリに入れていない。

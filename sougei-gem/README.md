## 全体の流れ

```
設定シート（①施設・車両 ②利用者）
   │ 🚐① 座標を作る        → ③座標（Googleジオコーダ）
   │ 🚐④ 実測時間を取る    → ⑤実測（Googleマップ経路。事業所↔全住所＋近い10件）
   │ 🚐② Gem用テキストを作る → ダイアログ＋Googleドキュメント「送迎データ（Gem用・自動更新）」
   ▼
Gem「送迎配車アシスタント」
   指示：Gem指示文_A1.md
   知識：配車ロジック.py ＋ 送迎データ（Gem用・自動更新）
   設定：コード実行ON、モデルPro
   → 入力部分（CONFIG/VEHICLES/USERS/STAFF/REAL）を書き換えて実行 → 送迎表
```

`🚐③ Gemの準備（初回だけ）` は `_payload` から `配車ロジック.py` を同じフォルダに書き出し、指示文を表示する。

## 配車ロジックの手順（配車ロジック.py）

1. 住所＋お迎え時刻が同じ人をひとまとめにする
2. 貪欲法で車に割り当てる（介護は車いす・歩行器の方を先に。時刻差30分超は同乗させない）
3. 車内の順番：最近傍法で回り、指定時刻／到着見込みで並べ替え
4. 4000回のシャッフルで移動時間の合計を短縮（seed固定で毎回同じ結果）
5. 時刻計算：停車1回ごとに乗降時間。指定時刻より早ければ待機
6. 2便の判断（介護のみ）：1便に乗り切らない、または6軒以上で平均10分以上早くなる場合
7. 移動時間は `REAL`（実測）を優先し、無ければ直線距離×factor

サンプルデータで実行すると、3台に10名が割り当てられ、未割当なし・警告なしで終わる。

## 2026-09-24 の作り直し

先方の名簿（放デイ・46名）を読ませて、次のように作り直した。名簿の実データはリポジトリに入れていない。

- **先方は名簿を保存するだけ**：1時間ごとの自動反映（トリガー）で、座標 → 実測 → Gem用ドキュメント を作り直す。名簿が変わっていなければ何もしない
- **曜日セルをそのまま読む**：`○(迎え14:10、送り17:55)` `○(自宅迎え9:40、…)` `○(迎え14:10/クラブ活動あり15:00、…)` `○(迎えなし、送りなし/送りあり：14:15)` など
- **お送り便に対応**
- **便を時間帯で分ける**：時刻が60分以上あく所で分け、保育園の便と小学校の便の両方で全車を使えるようにした
- **住所を整える**：全角→半角、ハイフンのゆれ、建物名・部屋番号を落とす、都道府県を補う。Googleが別の市町村と解釈した座標は使わない
- **職員を外した**：配車ロジックから運転手・添乗員の割り当てをなくした（版 2026-09-24）
- **Gem用データは Python のコードのまま出す**：Gemは見出しのコードを貼るだけで、書き写しによる変換をしない。実測表はその便に出てくる住所の分だけ載せる
- **確認が必要な点は `⚠要確認` シートに出す**
- メニューは「今すぐGemに反映する」「【初回】自動反映をONにする」「【初回】Gemの準備」の3つ

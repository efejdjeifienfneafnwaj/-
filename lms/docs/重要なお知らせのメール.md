# 重要なお知らせのメール（スマホに届ける）

## しくみ

| 役割 | 誰が |
|---|---|
| お知らせを「重要」にして配信し、宛先と文面を1行にまとめて表 `Lms_Mail_Form` に書く | ウィジェット |
| 行が増えたら、宛先の1人ずつにメールを送り、「送信済み」の印を付ける | Creator のワークフロー（最初に1回だけ設定） |
| どのアプリを開いていても上に赤い帯を出し、「確認しました」を押すまで消さない | ウィジェット |
| 誰が確認したか・メールが送られたかを見て、確認していない人にだけ送り直す | 管理者（e-ラーニング → お知らせ配信） |

宛先は、配信先（全員・職種・グループ）に当てはまる在籍中の人です。
本人がプロフィールで「重要なお知らせの受け取り先」（スマホのメールなど）を入れていればそちらに、
無ければ名簿のメールアドレスに送ります。どちらも無い人は、配信の画面と送信状況に名前が出ます。

## Creator に足す表：Lms_Mail_Form（レポート名 Lms_Mail_Report）

まとめた `lms-widget/PortalNavi.ds` には入っています。既存のアプリに手で足す場合は次の項目を作ってください。

| 項目名 | 種類 | 何が入るか |
|---|---|---|
| mail_key | 1行テキスト | 依頼ごとのカギ |
| ref_key | 1行テキスト | もとのお知らせのカギ（テストメールは `test`） |
| kind | 1行テキスト | `news`（配信時）・`resend`（送り直し）・`test`（テスト） |
| mail_subject | 1行テキスト | 件名（【重要】〜） |
| mail_body | 複数行テキスト | 本文（文字だけ） |
| mail_html | 複数行テキスト | 本文（改行を `<br>` にしたもの。メールにはこちらを使う） |
| to_list | 複数行テキスト | 宛先（カンマ区切り） |
| to_count | 数値 | 宛先の数 |
| requested_by | 1行テキスト | 依頼した人 |
| requested_at | 1行テキスト | 依頼した日時 |
| status | 1行テキスト | ワークフローが「送信済み」と書く |
| sent_count | 数値 | ワークフローが送った数を書く |
| sent_at | 1行テキスト | ワークフローが送った日時を書く |

あわせて、次の2つの表にも項目を1つずつ足します（`PortalNavi.ds` には入っています）。

| 表 | 項目名 | 種類 | 何が入るか |
|---|---|---|---|
| Lms_News_Form | important | 1行テキスト | 重要なお知らせなら `true` |
| Lms_Person_Form | notify_email | 1行テキスト | 本人が決めた受け取り先のメールアドレス |

## Creator 側の設定（最初に1回だけ）

1. Creator のアプリを開き、**ワークフロー → フォームワークフロー**で新規作成
2. フォーム：**Lms_Mail_Form**
3. 実行のタイミング：**レコードの作成時**（「作成または編集時」ではありません）
4. 動作：**送信成功時（On Success）**に「Deluge スクリプト」を選び、次をそのまま貼り付ける

```
cnt = 0;
for each a in input.to_list.toList(",")
{
    addr = a.trim();
    if(addr.contains("@"))
    {
        sendmail
        [
            from :zoho.adminuserid
            to :addr
            subject :input.mail_subject
            message :input.mail_html
        ]
        cnt = cnt + 1;
    }
}
rec = Lms_Mail_Form[ID == input.ID];
rec.status = "送信済み";
rec.sent_count = cnt;
rec.sent_at = zoho.currenttime.toString("yyyy-MM-dd HH:mm:ss");
```

5. 保存して有効にする
6. ウィジェットの **e-ラーニング → 設定 → 重要なお知らせのメール** で「自分にテストメールを送る」を押し、
   メールが届くこと、「送信状況を確かめる」で **送信済み 1通** と出ることを確かめる

1人ずつ送るので、ほかの人のメールアドレスは宛先に見えません。

## うまく届かないとき

- 管理画面の「メール」の欄が **送信待ちのまま 5分以上** になっている
  → ワークフローが無効か、タイミングが「レコードの作成時」になっていません。上の手順を確かめてください。
- **Creator に Lms_Mail の表がありません** と出る
  → `PortalNavi.ds` を取り込み直すか、上の表を手で作ってください。
- 「送信済み」なのに届かない
  → 迷惑メールのフォルダを確かめてください。携帯会社のメール（docomo・au・SoftBank）は、
    パソコンからのメールを受け取らない設定になっていることがあります。
    その場合は、送信元（Creator の管理者のアドレス）を受信許可に入れてもらうか、Gmail などのアドレスを
    プロフィールの受け取り先に入れてもらってください。
- Creator のプランごとに、1日に送れるメールの数に上限があります。
  人数が多い事業所では、契約しているプランの上限を確かめてください。

## 確認と送り直し

e-ラーニング → お知らせ配信 の一覧で、重要なお知らせには **確認（確認した人数 / 対象の人数）** と
**メール（送信済み・送信待ち）** が出ます。「詳しく」を押すと、

- まだ確認していない方の名前（メールアドレスの無い方は点線で囲って表示）
- これまでのメールの依頼と、それぞれの状態
- **確認していない方にだけもう一度メール** ／ **全員にもう一度メール**

が出ます。確認した印は、いいね・コメントと同じ表（`Lms_React_Form`、kind = `ack`）に残ります。

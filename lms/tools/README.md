# 確認用のツール

## スモークテスト.js
Chromium で実際にウィジェットを開いて、入口から管理画面までを通しで操作し、
「受講者に管理画面への道が出ていないか」を毎回確かめます。

```
npm install playwright-core            # 初回だけ
NODE_PATH=./node_modules node tools/スモークテスト.js
```

Chromium の場所が違うときは `CHROME=/path/to/chrome` を付けてください。

## テスト_コース編集.js
コースを作り、テストの設問と選択肢を打ち込み、保存して開き直すまでを操作します。

## テスト_ログインと権限.js
Zoho Creator にログインしている状態をブラウザの中で作り、
「誰がどのメニューを開けるか」を、システム管理者・部門管理者・受講者・
名簿に無い人のそれぞれで確かめます。

## テスト_名簿と職種.js
職員の1人ずつ登録、登録済みの方の編集（氏名・職種・権限）、氏名を直したときの
受講記録の付け替え、名簿からの削除、職種の追加・改名・削除を操作して確かめます。

## テスト_コネクト.js
3人が同じ Creator（テスト用サーバー）を見ている状態で、掲示板への投稿・いいね・
コメント・サンクスカード・削除・職種あての出し分けを確かめます。
社員表彰制度（管理者が表彰する・受賞者の掲示板に並ぶ・殿堂・メンバー一覧の受賞数・
受講者には表彰の欄が出ない）も確かめます。

## テスト_社内申請.js
社内申請が統合の枠の中で動くことを確かめます。一般の人でログイン → 休暇申請を出す →
上長の承認待ちに載る → 管理者には設定が出る、まで。社員・部署は統合側の名簿と職種です。

## テスト_プロフィール.js
顔写真（正方形・128px・JPEG に縮める）と自己紹介の保存、メンバー一覧、掲示板の顔、
端末の控えに写真を入れないこと、を確かめます。

## 申請を取り込む.py
shinsei/（先方からもらった社内申請）を lms-widget/app/js/shinsei と css/shinsei.css に
取り込みます。差し替えは最小限で、★統合 の印を付けています。shinsei/ 側を直したら再実行。

## dsを作る.py
3つのアプリ分のフォームを1つにまとめた lms-widget/FunaiPortal.ds を作ります。

## テスト_申請区分.js
社内申請の「設定・マスタ → 申請テンプレート」で、申請区分を画面から作る・直す・
「使わない」にする・また使う、を操作して確かめます。作った区分が「申請する」に並び、
入力欄が出ること、組み込みの区分を直しても承認経路と項目が減らないこと、
コードのかぶりや不正な入力が弾かれること、「経路」からその区分を選んだ状態で
承認経路の設定に入れること、まで。

## テスト_入口のカード.js
ログイン画面に並ぶアプリのカード（名前・説明・アイコン）を設定画面から変えられること、
触っていないカードは初期値のままであること、はじめの状態に戻せることを確かめます。

## テスト_リマインド.js
未修了の人の行が Creator の表（Lms_Remind）に用意され、修了すると「送らない」になり、
設定で止めると全員「送らない」になることを確かめます。

## テスト_新着と保存.js
2人が同じ Creator（テスト用サーバー）を見ている状態を作り、お知らせの配信・掲示板への投稿が
相手の画面に取り込まれてメニューに数字が出ること、Zoho のログインが切れたときに
「電波が悪い」ではなく切れたと分かる知らせが画面の下に残ること、視聴の保存が短い間隔で
行われることを確かめます。
あわせて、FunaiPortal.ds を取り込み直していなくて Creator に表が無いとき（code 2894）に、
その行だけを預かって後ろの視聴記録は届くこと、受講者に「電波」の知らせを出さないこと、
管理者にはどの表を入れ直すかを伝えることを確かめます。
さらに、条件付きの検索（criteria）を 400 で弾く Creator でも、保存が二重にならずに通り、
管理画面の読み込みが空にならず、1000件を超える表を続きまで読めることを確かめます。
名簿の氏名を変えて置き去りになった記録（名簿に無い氏名）が、管理画面の「ユーザー」から
今の名簿の方に付け替えられ、Creator の行が行番号のまま書き換わることも確かめます。

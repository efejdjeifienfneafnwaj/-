# 夜ノ街 — YORU NO MACHI

雨の夜の日本の繁華街を舞台にした、一人称視点のオープンワールド・クライムゲームです。ブラウザで動きます。
借金は三百万円、返済の期限は夜明け（ゲーム内 5:00、現実時間で約30分）。仕事をこなし、車を盗んで売り、警察をかわしながら金を集めます。

- **3Dモデル**：Blender（Python の `bpy`）のスクリプトで生成し、`.glb` で書き出しています。
- **ゲーム本体**：Three.js で作っています。
- **画像・音**：看板の文字、窓、路面、音楽、効果音はすべてプログラムで生成しています。画像や音声のファイルは使っていません。

## 遊び方

ビルドは不要です。ローカルでHTTPサーバを立てて開きます。

```bash
cd yorunomachi
python -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

`?q=low` を付けると、軽量モード（雨粒・人・車を減らし、解像度を下げる）で起動します。

| 操作 | キー |
|---|---|
| 移動 / 走る / ジャンプ | WASD / Shift / Space |
| 視点 | マウス |
| 撃つ / リロード | 左クリック / R |
| 車に乗る・降りる（運転中の人を引きずり下ろす） | F |
| 話す・仕事を受ける・自販機で買う・車を売る | E |
| アクセル・ブレーキ / ハンドブレーキ | W・S / Space |
| 運転席視点と後方視点の切り替え / クラクション | C / H |
| ラジオ局を変える | Q |
| 地図・一時停止 | M |

### 仕事

| 依頼主 | 仕事 | 内容 |
|---|---|---|
| ラーメン龍 | 出前 | 急ブレーキや衝突でスープがこぼれる。残量と速さで報酬が変わる |
| 金田 | 集金 | 滞納者3人を制限時間内に回る |
| 金田 | 逃がし屋 | 車で客を拾い、手配★3を振り切ってから降ろす |
| ヤマ自動車 | 車両の回収 | 指定の赤い軽自動車を盗んで運ぶ。傷が少ないほど高く売れる |

ヤマ自動車（解体屋）では、盗んだ車をいつでも売れます。パトカーは高く売れます。ただし手配中は買い取ってもらえません。

### 手配度（★）

- **上がる条件**：発砲、車両強盗、ひき逃げなどで上がります。
- **★の数**：多いほどパトカーの台数が増えます。
- **★3以上**：警官が撃ってきます。
- **下がる条件**：パトカーの視界から一定時間外れ続けると、手配が解除されます。
- **逮捕**：徒歩で止まったパトカーのそばにいると「逮捕」ゲージが溜まり、満タンで逮捕されます。
- **ペナルティ**：逮捕されると罰金、体力が尽きると治療費を払い、ゲーム内の時間も進みます。

## 構成

```
yorunomachi/
├── index.html / style.css      画面の骨組みと UI
├── src/
│   ├── main.js                 レンダラ、ポストエフェクト（ブルーム・色収差・周辺減光）、ゲームループ
│   ├── city.js                 街の生成（ビル・縦看板・電柱と電線・自販機・雨に濡れて反射する路面）
│   ├── textures.js             窓・看板・路面などのテクスチャをキャンバスで生成
│   ├── vehicles.js             車の物理、一般車の交通AI（左側通行）、パトカーの追跡AI
│   ├── carmodel.js             車の glb を1メッシュに統合（描画コール削減）
│   ├── peds.js                 歩行者（ビニール傘・逃走・転倒）
│   ├── player.js               徒歩・運転・拳銃
│   ├── missions.js / wanted.js 仕事と手配度
│   ├── hud.js                  HUD・ミニマップ・全体地図
│   ├── audio.js                Web Audio による効果音とカーラジオ（シティポップ／シンセウェーブ）
│   └── fx.js                   雨・パーティクル・弾道・夜空
├── blender/
│   ├── build_assets.py         Blender 用のアセット生成スクリプト
│   └── previews/               Blender で描画した確認用の画像
├── assets/models/*.glb         生成済みのモデル
└── vendor/three/               three.js r186（使用するアドオンのみ）
```

## Blender でアセットを作り直す

```bash
pip install bpy==4.5.14          # Python 3.11 用の Blender モジュール
python blender/build_assets.py            # assets/models/*.glb を再生成
python blender/build_assets.py --preview  # blender/previews/*.png も出力（Cycles CPU で描画）
```

Blender 本体からも実行できます: `blender -b -P blender/build_assets.py`

### Blender とゲーム側の決まりごと

- **向き**：モデルは Blender の +Y 方向を「前」にして作ります。書き出すと three.js 側では -Z が前になります。
- **名前**：部位はオブジェクト名で区別し、ゲーム側では名前で参照します。
  - `Body*`：塗装色を差し替える部分
  - `Wheel_FL/FR/RL/RR`：回転の中心になる空のオブジェクト（エンプティ）
  - `Light_Tail`：ブレーキ時に光る部分
  - `Light_Siren`：赤と青に点滅する部分
- **自分でモデリングした場合**：手でモデリングしたモデルに差し替えるときも、この名前の付け方を守れば、そのまま動きます。

## Unreal Engine へ移植する場合

- **モデル**：Blender のスクリプトは FBX でも書き出せます（`bpy.ops.export_scene.fbx`）。同じ手順で Unreal 用のアセットを作れます。
- **ロジック**：ゲームの処理（交通AI、手配度、仕事の状態の管理）は描画から切り離して書いてあります。そのため Blueprint や C++ に移し替えやすい構成です。
- **置き換える部分**：
  - 濡れた路面の反射 → Lumen の反射
  - 雨 → Niagara
  - 手続き生成しているネオン看板 → Unreal のマテリアル

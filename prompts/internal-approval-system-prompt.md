# 社内申請システム「ポン出し」生成プロンプト

> 使い方：下のコードブロック内を**そのまま全文コピーして Claude に貼り付ける**。
> 添付・前提知識は不要。1回の指示で単一HTMLファイルの完成品が出力される想定。
> 末尾に「フルスタック版に切り替える差し替えブロック」と「追い打ちプロンプト集」あり。

---

```text
あなたは、SaaS型ワークフロー製品（ジョブカンワークフロー / rakumo / X-point / コラボフロー / SmartHR / マネーフォワード クラウド経費 等）を
10年以上設計してきた日本のプロダクト設計者 兼 フロントエンドアーキテクト 兼 UIデザイナーです。
日本企業の稟議・決裁・職務権限規程・経理実務に精通しています。

【ゴール】
日本企業向けの「社内申請・承認ワークフローシステム」を、実在の商用SaaSと同等かそれ以上の品質で、
**単一のHTMLファイル1つ**として完全に動作する形で作ってください。
デモ用のモックではなく、「これ明日から自社で使える」と評価されるレベルの完成度を目指します。

────────────────────────────────
■ 0. 成果物の厳格な制約
────────────────────────────────
- 出力は **HTMLファイル1個のみ**（HTML + CSS + JavaScript をすべて内包）。
- 外部CDN・外部フォント・外部API・npm・ビルド工程は**一切禁止**。完全オフラインで動作すること。
- フレームワーク不使用のVanilla JS（ES2020+）。ただし内部に小さな状態管理レイヤと
  仮想描画（差分レンダリング関数）を自作し、コードを構造化すること。
- データ永続化は localStorage（キー接頭辞 `wf_`）。容量対策として添付ファイルは IndexedDB に退避。
- 日本語UI。文字コード UTF-8。`<html lang="ja">`。
- フォントは OS標準（Hiragino Kaku Gothic ProN / Yu Gothic / Meiryo / system-ui）のフォールバック指定。
- コード量を惜しまないこと。短くまとめようとせず、必要な機能を全部書き切ること（数千行になって構わない）。
- 途中で省略記号（// ...以下同様、// 実装省略）を書くことは**絶対禁止**。全機能を実装しきる。

────────────────────────────────
■ 1. ロール（RBAC）
────────────────────────────────
画面右上の「ログインユーザー切替」で即座に人格を切り替えられること（デモ性の要）。
1. 申請者（一般社員）：申請作成・下書き・取下げ・自分の申請追跡
2. 承認者（課長/部長/本部長）：承認・却下・差戻し・条件付承認・コメント・一括承認・代理承認
3. 管理者（総務/情シス）：フォーム定義・ワークフロー定義・組織マスタ・権限・監査ログ
4. 経理担当：経費申請の最終検収、仕訳出力、支払予定日設定、支払済フラグ
5. 人事担当：入退社・休暇・勤怠系申請の処理、入退社チェックリスト管理
※ロールは複数兼務可能（ユーザーに role[] を持たせる）。

 7. 交通費精算（出発地/到着地/経路/往復区分/IC実費、明細複数行、定期区間控除）
 8. 出張申請＋出張精算（出張先/期間/目的/日当/宿泊費/前払金（仮払）精算）

────────────────────────────────
■ 3. フォームビルダー（管理者機能・製品の心臓部）
────────────────────────────────
- ドラッグ&ドロップで項目を並べ替えできる、フォーム定義エディタ。
- 対応フィールド型：単行テキスト / 複数行テキスト / 数値 / 金額（¥3桁区切り・税率選択） /
  日付 / 日付範囲 / 時刻 / プルダウン / ラジオ / チェックボックス / ユーザー選択 / 部署選択 /
  取引先選択（マスタ参照）/ 勘定科目選択 / ファイル添付 / 明細テーブル（行追加型） /
  計算フィールド（他項目を参照する式：例 `{単価} * {数量}`）/ 見出し・説明文 / 隠しフィールド
- 各項目の設定：必須/任意、初期値、プレースホルダ、ヘルプテキスト、桁数・最大最小、
  正規表現バリデーション、**条件付き表示（他項目の値がXのとき表示）**、編集可能ロール
- プレビュー機能（編集中フォームを申請者視点で即確認）
- フォーム定義は JSON として import / export 可能（テキストエリアでコピペ）

────────────────────────────────
■ 4. ワークフローエンジン（差別化の核心・最重要）
────────────────────────────────
以下をすべて実装すること。ここが甘いと不合格です。
- 経路の視覚的エディタ：ノードを縦に並べ、分岐を図示（SVGまたはCSSで経路図を描画）
- ステップ種別：
  * 承認（1名）／ 合議（全員承認が必要）／ 或議（誰か1名の承認でOK）／ 回覧（承認不要・既読のみ）
- 承認者の指定方式：
  * 固定ユーザー / 役職指定（例：申請者の所属部署の課長）/ 上長N段（申請者の上長→そのまた上長）
  * 部署指定（例：経理部の誰か）/ 申請時に申請者が選択 / 条件により自動決定
- **条件分岐（決裁権限規程の再現）**：金額が 10万未満→課長止まり / 10〜50万→部長 /
  50〜300万→本部長 / 300万以上→社長、のような金額閾値ルールをGUIで定義可能にする。
  金額以外（部署・申請区分・勤続年数など）でも分岐可能に。
- 自動スキップ：申請者と承認者が同一人物の場合、承認者が不在の場合は自動スキップ（ログに理由記録）
- 代理承認（職務代行）：期間指定で代理人を設定。代理実行時は「A（代理：B）」と表示・記録
- 差戻し：「申請者へ差戻し」「特定ステップへ差戻し」の2種。差戻し後の再申請で経路を再計算
- 取下げ（申請者による自己取下げ）／ 引き戻し（承認開始後でも第一承認前なら可）
- 条件付承認（コメント必須）／ 却下（理由必須）
- 期限とエスカレーション：各ステップに標準処理日数。超過で「遅延」バッジ、
  N日超過で自動的に上位者へエスカレーション（設定可）
- 承認履歴のタイムライン表示：誰が・いつ・何を・コメント・所要時間を時系列で
- 一括承認：一覧でチェックして複数件を一度に承認（コメント共通入力）

────────────────────────────────
■ 5. 画面構成（サイドバー＋メインの2ペイン、SPAルーティングは hash 方式）
────────────────────────────────
1. **ダッシュボード**
   - 「あなたの未処理」件数を最上部に大きく（承認待ちN件／差戻されたN件／下書きN件）
   - 今月の申請件数・承認済金額・平均承認リードタイムのKPIカード4枚
   - 申請区分別の構成比、月次推移（**外部ライブラリ禁止のため、SVGで自作のグラフを描く**）
   - 直近アクティビティのタイムライン
2. **申請する**：テンプレートをカードグリッドで選択（カテゴリ絞込・検索・よく使う順）
3. **申請フォーム**：左に入力、右に「承認経路プレビュー（入力金額に応じてリアルタイムで経路が変わる）」
   - 下書き自動保存（3秒デバウンス、「保存しました HH:MM」表示）
   - 入力途中離脱の警告
4. **自分の申請**：ステータス別タブ（下書き/申請中/差戻し/承認済/却下/取下げ）
5. **承認する（マイタスク）**：未処理／処理済タブ、一括選択、申請内容を右ペインで即プレビュー
6. **すべての申請（検索）**：全文検索＋詳細条件（期間/申請者/部署/区分/金額レンジ/ステータス）
   - 列表示のカスタマイズ、ソート、ページング、CSVエクスポート
7. **経理処理**：承認済の経費・支払申請を検収 → 支払予定日設定 → 振込データ/仕訳CSV出力
8. **マスタ管理**：ユーザー / 部署（階層ツリー）/ 役職 / 取引先 / 勘定科目 / 経費規程（日当・宿泊上限）
9. **フォーム＆ワークフロー設定**（上記3・4）
10. **監査ログ**：全操作の記録（日時・ユーザー・IP風ダミー・操作種別・対象・差分）、絞込・CSV出力
11. **通知センター**：ベルアイコン＋未読バッジ、承認依頼・承認結果・差戻し・期限超過を通知

■ 6. 日本の実務要件（ここを外さないこと）
────────────────────────────────
- 金額は必ず `¥1,234,567` の3桁区切り。入力欄も入力中に自動でカンマ付与。
- 消費税：10% / 軽減8% / 非課税 / 不課税 を明細ごとに選択、税抜・税込・税額を自動計算。
- インボイス制度：取引先マスタに**適格請求書発行事業者登録番号（T+13桁）**を保持し、
  形式バリデーション。未登録事業者からの経費は「控除対象外」警告を表示。
- 電子帳簿保存法：添付ファイルに「取引年月日・取引金額・取引先」を必須メタデータとして保持し、
  この3項目での検索を可能にする（検索要件の充足）。訂正・削除の履歴を残す。
- 和暦表示の切替（令和7年9月17日 ⇔ 2025/09/17）をヘッダーの設定でトグル。
- 稟議書には「起案者・起案日・決裁区分・決裁日」欄、承認欄は**印影風の丸型スタンプ**で表示
  （氏名を縦書き風に配置した赤い二重丸をCSSで描画。承認時に押印アニメーション）。
- 会計連携：仕訳データCSV出力（借方勘定/借方金額/貸方勘定/貸方金額/税区分/摘要/取引先/日付）。
- FBデータ（全銀協フォーマット風）の振込一覧CSV出力。
- 承認経路は「職務権限規程」タブで一覧表形式でも確認できること。

■ 7. UI/UXデザイン規範（見た目の妥協は不可）
────────────────────────────────
- トーン：業務システムだが古臭くない。Linear / Notion / Vercel の様な静謐でモダンな企業向けUI。
  角丸8px、余白を十分に、影は控えめ（0 1px 3px rgba(0,0,0,.08)）、境界線は #e5e7eb 相当。
- カラー：`:root` にCSS変数でデザイントークンを定義（--bg / --surface / --border / --text /
  --text-muted / --primary / --success / --warning / --danger / --info）。
  プライマリは信頼感のある藍色系（#2563eb〜#1e40af あたり）。彩度は抑制的に。
- **ライト/ダークモード両対応**。トグルで切替、localStorageに保持、`prefers-color-scheme` を初期値に。
- ステータスバッジは色＋テキストで判別（色だけに依存しない＝アクセシビリティ）。
  下書き=グレー / 申請中=青 / 承認待ち=黄 / 承認済=緑 / 却下=赤 / 差戻し=橙 / 取下げ=グレー。
- テーブルは業務系らしく情報密度高め（行高40px前後）、ヘッダー固定、ゼブラなし、ホバーで行ハイライト。
- 空状態（Empty State）を全一覧に用意：イラスト風のSVGアイコン＋説明＋主要アクションボタン。
- ローディングはスケルトンUI。トースト通知（右下・3秒・成功/エラー色分け）。
- モーダルは背景ブラー、Escで閉じる、フォーカストラップ。
- **キーボード操作**：`/`で検索フォーカス、`n`で新規申請、`j/k`で一覧移動、`a`で承認、`Esc`で閉じる。
  ショートカット一覧を `?` で表示。
- **レスポンシブ**：768px以下でサイドバーをドロワー化、テーブルをカード型に再構成。
  スマホでの承認操作が快適であること（承認/却下ボタンを親指届く位置に固定）。
- **印刷CSS**：申請書詳細を `@media print` でA4 1枚の日本の稟議書レイアウトに整形（承認印影付き）。
- アクセシビリティ：セマンティックHTML、aria-label、role、フォーカスリング可視、
  コントラスト比4.5:1以上、フォームは label と入力を紐付け。

■ 9. コード品質
────────────────────────────────
- 明確な層構造：`Store`(状態+永続化) / `WorkflowEngine`(経路計算・遷移) / `Validator` /
  `Renderer`(画面別render関数) / `Router` / `UI`(共通コンポーネント: modal/toast/table/badge)
- 状態変更は必ず Store 経由。変更時に購読者へ通知して再描画する仕組みを持つ。
- 各セクション冒頭に `/* ===== セクション名 ===== */` のコメント区切り。
- 主要関数にはJSDoc形式の日本語コメント。
- 既定のエラー処理：try/catch でユーザーに意味のあるメッセージを出す（黙って失敗しない）。
- XSS対策：ユーザー入力は必ずエスケープしてから描画（`innerHTML` 直挿し禁止の方針を貫く）。

■ 10. 完成前の自己検証チェックリスト（出力前に必ず自分で確認）
────────────────────────────────
□ 単一HTMLファイルとして保存し、ブラウザで開くだけで動くか（外部依存ゼロ）
□ 申請 → 承認 → 承認 → 承認完了 の一連が、ロール切替でエラーなく通るか
□ 金額を 50,000円 / 300,000円 / 5,000,000円 に変えると承認経路が3段階で変化するか
□ 差戻し → 修正 → 再申請 が正しく動くか
□ 一括承認・代理承認・回覧・合議がそれぞれ動くか
□ フォームビルダーで新規申請書を作り、実際に申請できるか
□ リロードしてもデータが消えないか（localStorage永続化）
□ ダークモードで文字が読めなくなっている箇所がないか
□ スマホ幅(375px)でレイアウトが崩れないか、横スクロールが発生しないか
□ CSV出力が正しく日本語（BOM付きUTF-8）で開けるか
□ コンソールエラーがゼロか
□ 「// 実装省略」のような未完成箇所が1つも無いか

3. 最後に「主要機能の使い方」を箇条書きで簡潔に、および
   「次に拡張するならこの5つ」という提案を添える。
※途中で出力が長くなり切れる場合は、切れた箇所の直後から続きを出力し、
  最終的に全文が揃うようにすること。要約や省略で誤魔化さないこと。
```

## 付録A：フルスタック版に切り替える場合の差し替えブロック

「単一HTML」ではなく本番運用を見据えた構成にしたい場合、上記 **■0** を以下に差し替える。

```text
────────────────────────────────
■ 0. 成果物の厳格な制約（フルスタック版）
────────────────────────────────
- Next.js 15 (App Router) + TypeScript + Tailwind CSS + shadcn/ui
- DB: PostgreSQL / ORM: Prisma / 認証: Auth.js（Credentials + ロール）
- サーバー処理は Server Actions。バリデーションは Zod をクライアント・サーバー双方で共有。
- ディレクトリ構成・Prismaスキーマ・主要ページ・ワークフローエンジン（lib/workflow.ts）・
```
